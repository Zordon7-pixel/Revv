BACKGROUND (root-caused against a real Miles CCC ONE estimate PDF):
Miles uploads insurance estimate PDFs (CCC ONE format). The existing function parseEstimateTotalsFromPdfText in backend/src/routes/insuranceOcr.js (around line 182) SILENTLY RETURNS NULLS on real CCC estimates. Reason: pdf-parse extracts each totals row with the LABEL GLUED to the value, no separating space, e.g. the real line is:
  Body Labor48.2 hrs@$ 50.00 /hr2,410.00
The label finder uses anchors like /^Body Labor\b/i. The \b word-boundary cannot match between "Labor" and "4" (both word chars), so .find() returns nothing and hours/rate/cost come back null. Same failure for Paint Labor, Paint Supplies, Sales Tax, Parts, Subtotal, Net.

DELIVERABLES:
1. Harden parseEstimateTotalsFromPdfText so label matchers tolerate the label glued directly to the first digit/sign. Replace the /^Label\b/ anchors with patterns like /^Body Labor\s*(?=[-$0-9])/i (label, optional space, lookahead at a digit/$/-). Make the inner hour/rate regex and the tax regex tolerant of zero-space joins: e.g. "48.2 hrs@$ 50.00 /hr2,410.00" and "$ 7,136.73@8.8750 %633.38". Keep the existing takeTrailingMoney fallback.

ADD these categories to the totals object AND the parsed.estimate_totals contract (additive only): mechanical_labor_hours/rate/cost (CCC line: "Mechanical Labor2.2 hrs@$ 50.00 /hr110.00"), total_cost_of_repairs ("Total Cost of Repairs7,770.11"), net_cost_of_repairs ("Net Cost of Repairs7,770.11").
3. Expose a per-RO revenue value = net_cost_of_repairs, falling back to total_cost_of_repairs when net is absent. Surface it in the parsed contract (e.g. parsed.estimate_totals.revenue or a top-level parsed.revenue) so the RO/wizard can show "this job brings in $X".
